# U2 changelog

## v.next

* Inputs: Fixed `disabled: false` (and `input.disabled = false`) from plain JS turning the input off with no reason and taking it out of its form's verdict; `false` now means on
* Inputs: Added the `reason-boolean` usage report for `disabled: true`; where it is only reported, the reason reads "Unavailable" instead of "true"
* Inputs: Added the `bind-readonly` usage report: an input bound to a signal it cannot write (`bind: computed(…)`) is shown read-only instead of throwing on every keystroke; `readOnly: true` says it is read-only on purpose
* Inputs: Added `Input.specValue(value, readOnly?)`, which the spec registrations use to hand an input a spec's value, so an input bound to a read-only path (`bind: {value: '$.ro'}` over a computed) renders read-only instead of a spec error
* Form: Fixed a required empty field the user cannot reach holding the form, and a dialog's OK, off: an input inside an `inert` region (a `Section` off with a reason) is no longer counted
* Form: Fixed a form's verdict going stale when an input, or an element around one, becomes `hidden` or `inert` after the form is built; such a change re-judges the forms a microtask later
* Dialog: Changed (behaviour change) a close-only dialog whose CLOSE is off (`okDisabled`, or a form in it not valid) to close as a cancel on Escape and ✕ without running `onOK`; before, they ran `onOK` past CLOSE's reason
* Dialog: Fixed a footer button whose own reason turned on while an async OK ran coming back on when OK settled; the dialog now releases only the buttons still saying "Wait for OK to finish"
* Dialog: Fixed `getButton('Close')` returning the title bar's ✕ instead of the footer's CLOSE in a close-only dialog
* Dialog: Added the `close-only-cancel` usage report for `onCancel()` on a close-only dialog, which has no CANCEL
* Buttons: Added the `reason-missing` usage report for `button.disabled = true` on a u2 button that gives no reason; use `Reason.apply(button, '<why>')`, or `{disabled: '<why>'}` when it is built
* ChoiceChip: Fixed re-picking the value the chip holds firing `onInput`
* Lint: Improved `u2/no-unowned-root` to follow a package's own builders (`const panel = () => component(…)`) and to flag a control's `.root` handed to `grok.shell.newView`/`addView`, `DG.View.fromRoot`, `DG.Widget.fromRoot`, `ui.dialog().add` or `dockManager.dock`, naming `ViewHost.create`, `host(control)` or `ViewHost.of(view).dock`
* Lint: Fixed the `u2/no-unowned-root` message claiming that strict mode throws for a factory call
* Lint: Improved `u2/reason-text` to flag `x.disabled = <boolean>` and `x.setAttribute('disabled', …)` on a u2 control
* Lint: Added `...`, "Not allowed", "Cannot save" and a blank reason to the reasons `u2/reason-text` treats as empty
* Lint: Fixed `u2/reason-text` and `u2/no-unowned-root` taking their verdict from a variable of the same name in another function; they now resolve a name through its own scopes
* Ratchet: Fixed a new package's lint findings being recorded by its first `--update-baseline` instead of failing on growth: `check-consumer.mjs` counts a lint count that was never recorded as 0
* Styling: Added `u2-adaptive`, `u2-p1` and `u2-p2` to README › Styling as the documented utility classes; the lint and the ratchet no longer count them as internal selectors
* Styling: Removed `--u2-form-label-width` from the documented styling properties: Form sets it inline when it measures, so a package's value never applied
* Styling: Added `css/motion.css`: under reduced motion the dialog's busy spinner, the notify countdown and the chevron and switch transitions stand still
* Samples: Changed "A list with details" to a `MasterDetail` with `--u2-master-detail-height`, as the rule says, instead of a hand-built splitter
* Docs: Changed AGENTS.md to write the owner verbs as `owner.build`, `owner.task`, `owner.subscribe` and `owner.own`
* Docs: Added to AGENTS.md how to open an app (`grok.shell.addView(ViewHost.create({…}).view)`) and that a lint finding alone is a warning
* Docs: Changed README to mark the rules that no check holds as docs only
* Testing: Fixed `tests/dom-shim.js`'s `document` missing `contains`, which a browser's has, so an observer on the whole document failed under the shim
* Testing: Fixed the DOM shim (`U2_DOM=shim`) not notifying attribute observers: `setAttribute` and `removeAttribute` now notify them, honouring `attributeFilter` and `subtree`, and observers get their records
* MasterDetail: Documented that it renders every row, so it is for lists up to a few hundred items; a longer list is a `VirtualList` beside a detail of your own, in a `Splitter`
* tableFromMap: Fixed an element value's cell (a molecule drawing) carrying a text row's 22px height and `overflow: hidden`: the value cell takes the element's height and clips nothing that reaches past it; a text row stays 22px
* FilterBuilder: Fixed a disabled builder's own buttons (and/or, not, add, remove) saying no reason and its links (Advanced, Add condition, Flatten) still working from the keyboard: each carries the builder's reason and does nothing while it is off
* Inputs: A read-only input's editing options (the colour swatch, the number clicker, the pickers) are off with the reason "Read-only" instead of a focusable button that does nothing; a read-only slider takes the pointer again, so its value shows on hover (a drag or a key still does not move it)
* Form: Fixed `maxWidth`, and a `Page`'s, being ignored once an auto form turns wide
* Designer: In Design mode the canvas says why its controls do not work ("Switch to Run to use the controls")
* ViewHost: Fixed a scripted press on a table view's parent crumb leaving no view current: `breadcrumbs.onClick` runs once the shell has made the parent current
* Entry points (breaking): `@datagrok-libraries/u2`, `/dg`, `/filter`, `/dg/filter` and `/testing`, the test helpers under `/tests/…` and `/css/icons.css`, `/css/theme-dark.css`; `src`, `src/dg`, `src/core/filter`, `src/dg/filter` and `src/testing` are aliases of the entry points, and any other `src/…` path no longer resolves
* Values (breaking): `input.value` is the plain value — followed inside an effect or a `computed`, written by assignment — `input.peek()` reads it untracked and `input.signal` is the signal to wire (`bind: input.signal`, `span(input.signal)`); the same on `AsyncValue`, `ProgressBar`, `Combobox` and `StateSource`. `scripts/codemod/u2-v1.mjs` rewrites `x.value.value`, `x.value.peek()` and bare signal uses
* Reason (breaking): every "off" carries the reason the user reads — `disabled: Reason` (`string | null`, or a signal of it) on inputs, buttons, icon buttons, actions, menu items, menu bar items, button group items, wizard actions, tree nodes and ribbon buttons, and `setDisabled(id, reason)` on `ButtonGroup` and `MenuBar`; `enabled`, `setEnabled`, `okEnabled` and boolean `disabled` are gone, `okDisabled(reason)` and a wizard's `canProceed` take reasons only. `Reason.apply(el, reason)` writes `aria-disabled` and the reason as `aria-description`; a reason is the tooltip. Wizard steps not reached yet, a busy footer, a locked filter row, inherited and locked access boxes, the designer's verbs and an empty message's Send now say why. A spec prop `enabled` is a parse error naming `disabled`. `TagsInputOptions.deleteEnabled` is `deletable`
* Dialog: `{closeOnly: true}` — one CLOSE and never a CANCEL, for a dialog whose work applies as it is done; CLOSE, ✕ and Escape all close as OK
* Bridges: a platform input the platform turned off is off in u2 with "Not available here", and u2's reason turns the platform input off; an editor the platform turns off (`ui-input-disabled`) says why — the tooltip the platform gave it, else "Not available here"
* Owners (breaking): an owner is the receiver or an `{owner}` option, never a positional argument — `owner.subscribe(source, handler)` (the free `subscribe` takes whoever is building), `toSignal(observable, initial, {owner})`, `bindText(el, source, {owner})`, `bindValue(input, source, {owner, commitOn})`, `Tooltip.bind(el, content, {owner})`, `Overlay.show(anchor, content, {owner, …})`, `Menu.bindContext(el, {owner})`, `Input.bindOwned(fn, {owner})`, `frameRows(df, {owner})`, `new FrameRows(df, {owner})`, `collectionSelection(source, rows, {owner})`, `new ViewSync(host, {owner})`
* Captions (breaking): a caption is named by its role — an action's, an action group's, a designer action's, a button group item's, a menu bar item's and a ribbon action's is `text` (an action's `name` is now its automation id, the text by default), a tab's is `title` (`TabOptions.title`, `TabStrip.setTabTitle`)
* Inputs (breaking): `addOptions` takes a button or a link (`iconButton(…)`, `button(…)`, an anchor) — the rail no longer takes a drawn element
* Codemod: `scripts/codemod/u2-v1.mjs` also moves positional owners, renames `runInScope` to `build`, `Scope.runWith(s, fn)` to `s.build(fn)` and the role captions, rewrites the removed view wrappers through `ViewHost`, a path inside u2 to the entry point that exports what it takes, a `run` or key handler that hands back a value, and a spec document's `enabled` — type-checked against the u2 the code compiles with, and reporting what it cannot finish (a reason to write, a name on no entry point, a `.value.value` through a local cast). Run twice, it changes nothing the second time (`tests/codemod.test.js`)
* Inputs (breaking): The required check comes before the validators — an empty value `required` (or `nullable: false`) refuses never reaches them — and blank text is empty in `TextInput` and `TextArea`. An editor holding text it cannot read (a number, a date, a color, a typed file path) is not empty: its own message still shows. A file, files or key input says its own "Can't be empty." / "At least one file is required." for `required: true` too
* Inputs: `onEnter` / `onEscape` handlers answering `false` decline the key, which goes on to the form or the dialog (Escape cancels it); `focus({select: true})` selects the text in a text editor
* Actions (breaking): an `Action`'s, a ribbon action's and a ribbon button's `run` returns a promise or nothing (`() => void | Promise<void>`): a `DG.Row` handed back by mistake is a type error
* Exports: `ChoiceInputOptions`, `MultiChoiceInputOptions`, `TextInputOptions`, `TextAreaOptions` and `BoolInputOptions` from the root, as every other input's options
* Format: `plural` counts and an object form's date-only field go through `Format` (a date-only field's pattern now knows every platform token — `yy`, `ddd`, …)
* Controls: `dispose()` called by hand takes the control off the page (engine: needs the js-api build carrying it); one disposed because its owner went leaves the DOM to whoever holds it
* Testing: The node runner (`scripts/run-tests.mjs`, u2's and ems' `npm test`) runs u2 strict: a usage error throws (`U2_STRICT=1`; `U2_STRICT=report` lists them all). `tests/owned-test.js` (also `@datagrok-libraries/u2/tests/owned-test.js`) is `node:test`'s `test` with the test as the owner of what it builds — its body under a root scope disposed when it ends, `testOwner().build(…)` after an `await`.
