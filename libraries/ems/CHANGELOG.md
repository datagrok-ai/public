# EMS changelog

## v.next

* Properties: Fixed the save confirmation listing only what you changed: it lists everything destructive in the server's plan that your changes do not already say (dropped tables and columns with the values they hold, type, unique, auto-numbering and business-key changes, dropped constraints), and a destructive plan waits for a checkbox that names all of it ("Delete 3 stored values", "Change the type of 1 column") before SAVE
* Properties: Fixed a column you added showing as a locked plugin column after a reload, and adding the next column deleting it with its values: Edit properties reads who owns each column from the registry (`DomainTable.userColumns`), on open and after a conflict reload, and every extension sends all your columns back; on a server too old to say who owns a column, Edit properties refuses to open rather than risk deleting them
* Properties: Fixed two people editing a table's properties at once silently dropping each other's columns: a save names the extension version the dialog was opened at, so a concurrent change is a conflict that reloads with your edits on top
* Tree: Fixed the Stockroom Locations tree never showing another session's rename, insert, move or delete of a location (a deleted node could still be picked and read "0 containers"): `domains.tree(table, {follow: source})` watches the tree's table on a live source's probe (`DomainSource.watch`) and reads the roots and every open branch again, keeping the selection on its row; a selected node a peer deleted gives way to its parent, or to nothing, with "<name> was deleted" under the tree; while the followed source or its session holds pending changes, the deleted node stays selected (nothing bound to it is rebound) and the tree says "<name> was deleted — save or discard your changes to leave it", moving to the parent once they are saved or discarded. Stockroom's tree follows its containers source
* Table view: Fixed aggregation columns (a count or sum over a child table) keeping the old value after a child was saved (an issue added from the project page, then Back) or written by another session: they are read again when this browser saves a table they aggregate, and the list's live probe now also asks each aggregated table (once per table, the change token where the backend keeps one) and reads them again when it moved. `DomainSource.watch(address, moved)` follows another table on a source's probe
* Lists: Fixed a query, search or sort changed while edits are pending never being applied after Discard (or Save): the list kept the old query's rows under a search box saying otherwise; the re-query skipped over the pending edits now runs when the source turns clean, by comparing what the shown rows were read for with the current scope
* Live refresh: Fixed another session's write moving the current row (a list jumped to another row; a form bound to `currentRow` lost it) and clearing the selection: a reload of the same collection (the live poll, a peer's save, Refresh) re-reads the window shown, every loaded page, and swaps it in place as the re-base after a save does, so the current row and the selection stay by id and the current row is never null on the way (a child collection under it is not rebuilt), also when a save's re-base swapped the rows while the reload was in flight; a current row the peer deleted hands on to its neighbour; a filter, search or sort change still starts over
* Live refresh: Fixed a child row typed while its clean parent's reload was in flight (a peer's save, the ribbon Refresh) being dropped when the reload landed: a reload of the same collection keeps the shown rows when the session gained changes meanwhile and shows "Data changed" with Refresh instead; a filter, search or sort change still lands
* Table view: Fixed the status bar counting one selected row however many were picked in the table, a list's selection shrinking to the current row on switching to the table, and the current row painting like the other selected rows: the list kept its own selection binding alive under the table and the two overwrote each other's rows in the frame; the list now stands aside while the table is shown, the table takes over the frame's selection, and the current row has its own colour (the list's)
* Lists: Fixed Save of a deleted current row deselecting the other selected rows and selecting the row the current row moved to: the current row moves to the deleted row's neighbour and the rest of the selection stays
* Live refresh: Fixed a list never noticing another session's write that landed between its load and its first poll (up to 30 s): a live load reads the probe's baseline just before its rows, so the first poll compares instead of adopting the write; the poll, like a peer's save, no longer reloads a source whose session holds pending changes (a child tab's rows) — it shows "Data changed" with Refresh instead. The same holds after a save or a re-base when rows shifted (the re-read takes the baseline before its window), and over a load that kept pending changes (the shown rows' baseline stays). A live list's load and re-base ask one more cheap read (the change token, or the count over a filtered list). Known limit: a list loaded with `live` off and switched on later baselines on its first poll
* Lists: Fixed scrolling while another session writes repeating a row (after an insert) or skipping one (after a delete or an update that moves a row): after each page the source checks that the row its window ended on is still at that offset, and when it moved re-reads the window and the total, as after its own save; a page never appends a row the list already holds, and "N of M" is recounted when the last page lands. Over pending changes the list shows "Data changed" instead of dropping them, and re-bases on the next page once they are saved or discarded. Known limits: an insert and a delete before the window that cancel out are not seen; with ties on the sort column (EMS-082) a page may re-read the window with nothing written
* Live refresh: Fixed saving in another view of the same table (an issue saved from its project page) silently discarding an entity page's unsaved child rows (a new or edited comment): a source whose session has pending changes is no longer reloaded under them; it shows "Data changed" with Refresh instead
* Save: Fixed a delete or restore of a record another session changed meanwhile landing silently over the change: the ops carry the version the record was read at, and a stale one is refused as a version conflict (the conflict dialog on the platform) like a stale edit; the memory backend refuses it too. The server honours the version once core passes it to delete and restore; until then it is ignored
* Apps: Fixed a grant made while the app is open never reaching it: opening the app or a view and the ribbon's Refresh now read the caller's access afresh (the platform caches it with no expiry), the no-access page offers Refresh, and New and the ⋯ menu follow once the access reads View
* EMS-032: Fixed a refused new record (Edit or Insert revoked meanwhile) not re-gating the app on today's servers: their refusal carries no code and says "Insufficient privileges to insert into …", which is now recognised as forbidden like the bare "forbidden" of an update or delete, so New and the ⋯ menu go
* Save: Fixed the balloon announcing changes as saved after RELOAD in the conflict dialog dropped them ("Item saved", "2 changes saved" with one landed): it counts only what the server wrote, says "Reloaded; your changes were discarded" when every change was reloaded away, and `save()` then answers false
* Save: Fixed Save and Ctrl+S staying off after the server refused a save whose cause was then removed elsewhere (the clashing row deleted in another tab); the refusal stays shown on the field and the status line, and Save sends the batch again for the server to decide. A client error and a save refused as forbidden still hold Save
* Save: Fixed Save staying off after a refused save of several sources once its cause is gone — the offending field fixed (back to its original value too), the offending child row fixed, or one of two overlapping edits discarded; the refusal copied onto the other sources now goes with its cause, and stays while it holds
* Apps: Fixed a user without View on the table being told "No items yet" on the list and `Item "<id>" was not found.` on a row's page: both now say the user has no access to the table and to ask its owner, with no New, Save or Discard. A row opened from a list loaded before View was revoked drops the cached access once and reads it again, instead of saying the row was not found
* EMS-032: Fixed a save the server refused as forbidden (Edit revoked meanwhile) leaving the app on the access it was built from: the platform access caches are dropped and every source of the session re-reads its access, so the form turns read-only and New, Import… and Bulk edit… go without a reload; the status line says "Cannot save: you do not have permission to make these changes. Discard the changes, or ask the table's owner for access" instead of "Cannot save: forbidden". Recognised on today's servers too, whose js-api refusal has no code (the bare "forbidden" message), and on a save that throws; the writer a grid edits through (lists, children grids) is rebuilt under the new access at once, or after Discard where pending changes hold it
* [core#611](https://github.com/datagrok-ai/core/issues/611): Domain schemas: a named error code for an unknown group on grants — the binding dialog reads `unknown-group` instead of matching the message
* History: Fixed "Show older" turning off with no reason while it loads; it now says "Loading older entries…"
* u2-domain-pick: Fixed a pick bound to a read-only path rendering a spec error instead of a read-only input
* u2 v1: Moved onto u2's v1 API (plain `value`/`peek()`, `build`, owners as options, captions as `text`, `disabled` reasons, entry-point imports). Save and Discard say why they are off ("No changes to save", "Nothing to discard", "Wait for the batch being saved to finish"), as do the authoring dialogs' and the manifest editor's controls that are off, and New says "Loading…" until its table is loaded; `DomainAction` takes `disabled` (the reason) instead of `enabled`, and the `u2-domain-pick` tag's `enabled` prop is `disabled`
* Forms: Fixed text a number, date or color field cannot read ("abc") not counting as an unsaved change: Discard drops it and the gates ask before leaving
* Properties: Added an editor for users' own columns on a plugin's extensible tables, opened from Edit properties… on the list's ribbon (`domains.editProperties`); the plugin's columns stay read-only, and a save that deletes values asks first
* Forms: Fixed a field left invalid going stale in the app: the breadcrumb and the entity page's status name the record as its fields read (an emptied title is "New issue" again, not the last valid one; a saved record's emptied name leaves the name it has, never a blank crumb), and a field over a cell already changed is no second unsaved change ("2 unsaved changes" for one edited title). `holdUnwritten` takes what the fields hold for their row (`UnwrittenEdits`); added `DomainSource.current(row)`
* Import: Fixed writing the key back failing ("Column named 'Sku' already exists") when the source table has a column of that name in another case (`sku`): column names ignore case, so the key goes into a column of its own beside it, and the source's column keeps its values
* Import: Fixed the key written back, and the report's key column, holding each row's caption ("Row 1", its name) instead of its key: a one-column key is its own value, as the column's format spells it (`DG-000060`)
* Import: Fixed closing the dialog while the report reads the keys back building its rows table under the closed dialog (a u2 usage error); the key is still written back
* Apps: Fixed browser Back or Forward inside an app's view (`domains.views`) opening a second view of the table: the app function the platform asks again answers no view, and the open one takes the address; with unsaved changes the gate asks once
* Forms, Import: A required field is starred through the input's own `required`, so it is `aria-required` too (the asterisk was a class set by hand)
* Apps: Fixed "Wait for the batch being saved to finish." showing when a record made with New is saved, then deleted from its own page and saved again: the saved delete no longer reads as a discarded draft, and the app goes back to the list once
