# Domain UI changelog

## v.next

* Build: `datagrok-api` is now the in-repo `../../js-api` rather than `^1.27.8` from the registry. Both consumers (ApiTests, Grit) already resolve it that way, and a second registry copy under this library's `node_modules` gave every `DG.*` type a duplicate identity, so consuming packages failed to compile (`Types have separate declarations of a private property '_helpUrl'`). The `npm link` scripts are gone — `npm install` creates the symlink directly.

* GROK-20298: `DomainFrameEditor`, `DomainGrid`, `confirmDiscardChanges` / `promptUnsavedChanges` and the widget-action Funcs now live in `datagrok-api` (`DG.*`) and are re-exported from here — every import path is unchanged, and the names are the SAME classes, never a copy. On the platform surface the generic members are statics (`DG.DomainFrameEditor.SERVICE_COLUMNS`, `DG.DomainGrid.saveFunc`, ...); this library keeps the flat names (`SERVICE_COLUMNS`, `saveFunc`, `validateCellValue`, `isReferenceProperty`, `editorsOf`, ...) bound to them, so no plugin edit is needed. The library keeps the composable plugin surface (`DomainAppView`, `EntityListWidget`, `DomainForm`, the `domains` facade, the handler helpers). The grid's slice of the stylesheet moved with the grid. The `datagrok-api` floor is now `^1.27.8` — the version that carries the moved classes; an older platform fails the shim import at build time instead of at runtime.

* GROK-20298: `DomainTable` and `domains.table()` take a fifth generic, the update payload (`DomainTable<TRow, TInsert, TColumn, TExpand, TUpdate = Partial<TRow>>`), so a handle over a table with many-to-many relations keeps `update()`'s link sets typed; `AnyDomainTableClient` erases it like the rest
* GROK-20298: `DomainGrid` leaves `ref` cells EDITABLE too: the platform's grid opens the domain lookup picker anchored on the cell, so column security (`writableColumns`) is now the only in-grid editing gate. Clearing a reference cell (DELETE / BACKSPACE) reaches the wire as an explicit `null`, and a required reference then blocks the save with "Value can't be empty"
* GROK-20298: `domains.db(schema)` — the schema-level async boundary: resolves a `DomainTable` handle for EVERY table of the schema in one go (`const db = await domains.db('grit'); db.issues.app()`), each table a direct camelCase PLURAL property (`db.issues`, `db.issueLabels` — `pluralizeTableName`, mirrored by the `grok api --ui` codegen so typed `<Schema>UiDb` interfaces bind to the runtime handle); declared table names stay singular in `db.tables` / `db.table(name)`
* GROK-20298: The `DomainTable` handle's widget factories are typed over its generics: `form`/`formDialog` seed values check against the insert payload, `grid` checks `query` and `defaults`, `list`/`listView`/`app` check `query` — a misspelled column on a typed handle (codegen `<Table>Ui.table()` or a `domains.db` property) now fails compile; untyped handles are unaffected
* GROK-20298: `DomainGrid` leaves user and group cells EDITABLE: the platform's grid now opens its own picker anchored on the cell for `User` / `Group` semType columns (a name is written back as an id, and the cell renders the avatar and name); forms and the batch paths keep excluding every reference column (`isReferenceProperty`)
* GROK-20298: A `DomainForm`'s user and group columns are edited with the PLATFORM's own pickers (`ui.input.user` / `ui.input.userGroups`, single-select) instead of the generic `RefInput` type-ahead — the same controls the Dart row editor uses, with their server lookup, avatar tags and clear affordance; the value written stays the user's (or group's) id, the picker is seeded from the row's id like the Dart editor seeds its own, and the machine surface is unchanged (a `props` write still resolves a display name through the same suggestion source, reports ambiguity as a validation error, and `getWidgetStatus().inputs` still reports `type: 'ref'`). Domain-table references keep the `RefInput`
* GROK-20298: `RefInput`'s search icon now opens the lookup picker as a drop-down anchored below the input (the headless flavour — closes on the picking click, an outside click, or ESC) instead of the modal dialog; `domains.pick(table, {anchor})` passes the anchor through for callers that want the same
* GROK-20298: A composed `domains.view` page no longer repeats the whole action vocabulary per child (`Save, Discard, Reset, Save, Discard, AddRow, ...`): its ribbon shows ONE page-level Save and Discard, which drive every editor of the page exactly as its status bar does, plus each child's EXTRA actions (Reset, AddRow, DeleteRow, Refresh, a custom action), labelled with the child's table when more than one child offers the same one. The machine surface is untouched — every child's `getFunctions()` and the page's own still report the full set
* GROK-20298: The `DomainTable` handle is typed over all four client generics (`DomainTable<TRow, TInsert, TColumn, TExpand>`), so `domains.table(typedClient)` — and the generated `<Table>Ui.table()` — carry the table's insert payload, column union and expand keys into `query`/`queryDf`/`count`. The reflective widgets keep taking a generics-erased client, now spelled `AnyDomainTableClient`
* GROK-20298: Completed the handle: `grid(options)`, `list(options)`, `listView(options)`, `entityView(row|id, options)` and `app(options)` join `form` / `formDialog` on the `DomainTable` the `await domains.table(...)` returns. Every factory is SYNCHRONOUS — the widget exists at once and its rows load inside it (`DomainGrid.ready` / `EntityListWidget.ready`, resolving into a visible error state rather than rejecting) — so a whole CRUD app is `(await domains.table('grit.issue')).app()`
* GROK-20298: `DomainGrid` and `EntityListWidget` are now `DG.Widget` subclasses: their subscriptions ride the inherited `subs`, `detach()` chains `super.detach()`, both implement `IEditorHost`, and both report themselves through `getWidgetStatus()` (parts, what they are showing, the pending count, the first blocking error) and `getFunctions()` (`Save` / `Discard` / `AddRow` / `DeleteRow` / `Refresh` from the shared vocabulary, permission-gated). Grids expose NO per-cell `inputs`: their machine surface is status + functions + the `dataFrame`, which is a first-class platform object already
* GROK-20298: **Insert forms are pristine until touched.** A `'new'` row nobody has written to contributes nothing to `changeCount` / `isDirty` (`DomainFrameEditor.addRow(values, {pristine: true})`, which is how a form seeds its row), so an untouched New form — however prefilled — closes silently and arms neither the unsaved-changes gate nor `beforeunload`; the first user or machine write flips it. A row added by a user gesture (the grid's Add row) is pending immediately, as before, and `DomainForm.reset()` restores the pristine state
* GROK-20298: **One router per app.** The app's root page (`DomainAppView`) is the only view that accepts the app's URL prefix; row pages and `domains.view` pages return `acceptsPath === false`. Its `handlePath` reconciles: `entity=` FINDS OR ACTIVATES the row page for that id (re-running its `restoreFromUrl`) and opens one only when there is none, and without it the list restores itself. Back / forward onto a row's URL no longer stacks a duplicate page, and which page handles a Back no longer depends on the order the views happen to sit in
* GROK-20298: The entity page's Details pane is a `DomainForm` in edit mode — the hand-rolled value diff, its `_update` retry and its Save/Revert buttons are gone. Save now goes through the form's one-row editor (one transaction, per-field markers, the standard 409 dialog), the form's functions ride the ribbon, and its pending changes join the page's status bar and gate. The page no longer offers the Open action for the row it is already showing
* GROK-20298: Added the `actions` option to lists, list pages and row pages — `(row, defaults) => actions`, applied wherever the handler's permission-gated actions are consumed (a row's context menu, the row page's ribbon). A `DomainRowAction` may declare `changesRow` explicitly, which now decides whether a list or a page reloads after it ran (the platform's own actions keep the icon-keyed default); a CANCELLED action (`run()` returning false) no longer reloads the row page and pops its prompt
* GROK-20298: `AppView` gained the aggregating machine surface every page shares: `widgets` (what the page hosts), the editors rolled up from them, `getWidgetStatus()` nesting each child's status under a path-prefixed name, and `getFunctions()` merging theirs — `domains.view` is now that base plus a layout
* GROK-20298: `DomainFrameEditor.forContext(context)` builds an editor with no round trip (everything `attach` awaits is in the prefetched handle), `acquireDomainContext(client)` is the one place that resolves it, and `_resetCaches` now also drops the pre-edit SNAPSHOTS — an external `removeAt` used to leave a stale key on which `beginEdit` early-returned and the next `commitEdit` recorded another row's original value
* GROK-20298: `validate()` covers columns the registry does not declare, so a prefilled value on one that `buildOps` would drop is marked instead of vanishing; the row-cap banner of an entity page's child grid no longer collapses the grid to 400x300 (its wrapper is scoped like the tab host's)
* GROK-20298: **Breaking (reverted):** `EntityListWidget.create()` resolves to an `EntityListWidget` again, not `EntityListWidget | null`. Gating the FIRST load belonged to the page that swaps lists, not to the list that does not exist yet — `DomainAppView.load()` prompts before it builds a replacement, and every rebuild of a LIVE list still goes through `EntityListOptions.confirmDiscard`
* GROK-20298: Added the `domains` facade — `import {domains} from '@datagrok-libraries/domain-ui'`. `domains.table(nameOrClient)` is THE async boundary: it prefetches the typed client, the registry properties, the table info and the caller's capabilities ONCE and returns a `DomainTable` handle whose widget factories are SYNCHRONOUS (`form`, `formDialog`, plus `query`/`queryDf`/`get`/`count` passthroughs; the grid/list/app factories land next). Capabilities are a snapshot taken at acquisition — re-acquire the handle to re-gate after a grant change. Also on the facade: `domains.view(widgets, options)` / `domains.formView(widget)` (a page hosting any `DG.Widget`s, reusing `AppView`'s status bar, unsaved-changes gate and beforeunload, with the children's editors rolled up into one dirty state and their functions merged onto the ribbon), `domains.dialog(widget)` (OK saves — a failed save keeps the dialog open — while Cancel/Esc/a programmatic close discard silently and resolve false, with a first-answer-wins guard so no promise is ever stranded), and thin delegates to the shipped one-shot openers (`pick`, `create`, `edit`, `conflictDialog`, `auditPane`, `grantsPane`, `open`, `deepLink`)
* GROK-20298: Added `DomainForm extends DG.Widget` — the property form of ONE domain row over a one-row `DomainFrameEditor`, so dirty state, validation, the 409 flow and the transaction are the grid's. Inputs come from the registry (writable columns only), reference/user/group columns render as the new `RefInput` (async type-ahead over the target's display names, a search icon opening the platform's picker, a clear icon honoring nullability, and display-text → id resolution that reports ambiguity as a validation error instead of throwing). Construction is synchronous — the inputs, `getInput`/`replaceInput`/`addValidator`, `props` and `getWidgetStatus` all work immediately, values written before the row loads are buffered — while the row loads behind the platform's update indicator; `ready` is idempotent and resolves into a visible error state rather than rejecting. Also exported: `bindAsyncValidator(input, probe, {debounce})` and `mapServerError(e, ctx)` (ARCHITECTURE §9's mapping: per-field markers, form banner, duplicate, the 409 dialog, 403 → balloon + capability-cache invalidation)
* GROK-20298: The machine surface, on the platform's own widget protocol: `DomainForm.getProperties()` returns registry-derived `DG.Property`s wired THROUGH the editor (so `form.props['title'] = 'x'` takes the single-writer path a keystroke takes, and a ref property accepts a display name), `getWidgetStatus()` reports named parts, a registry-derived description, the first pending error and the new `IWidgetStatus.inputs` array read live, and `getFunctions()` returns REAL platform Funcs from one shared, idempotently registered vocabulary (`DomainUi:Save` / `Discard` / `Reset`, each `//input: widget widget`, tagged `domain-ui,widget-action`), permission-gated. `domains.view` pages nest their children's statuses under path-prefixed names and merge their functions. `DG.Widget.getAll()` finds a form because it registers itself with the platform (`toDart()`) at construction
* GROK-20298: Added `DomainFrameEditor.forRows(client, values, options)` — an editor over rows built locally from the table's declared columns (the insert path of a form, no query round trip), and the `IEditorHost {editors}` interface plus `editorsOf(widget)` for the dirty rollup a container performs
* GROK-20298: The unsaved-changes gate now holds on EVERY path: `EntityListWidget.create` resolves null when the first load is refused (so a page keeps the list — and the pending batch — it already has), `DomainAppView.load()` aborts on a refusal and republishes the URL of what is actually on screen (a cancelled browser Back no longer destroys the batch), overlapping loads are generation-guarded, `DomainEntityAppView.back()` and the post-Delete close go through the prompt (a Delete discards the child editors explicitly and says so), `AppView.confirmDiscard` is re-entrant (two racing gestures share one dialog), and a `beforeunload` handler is registered exactly while the page is dirty, so a tab close or a page reload asks too
* GROK-20298: A value on a column the caller cannot write is now marked `kind: 'error'` and refuses the save on NEW rows as well as modified ones — a `DomainGridOptions.defaults` parent FK the user may not write used to be dropped from the insert payload silently, saving a child row with a null FK
* GROK-20298: `DomainFrameEditor`'s per-row caches and running change count are reset when the frame's rows are added or removed by anyone else (they are keyed by row index, which every external removal shifts); `validate()` is refused during a save like the other mutators
* GROK-20298: `EntityListWidget` search fixes: the identity columns are narrowed to declared, non-reference STRING columns as the built-in Domain View does (a `like` against a uuid column errors server-side), the term's own `%`/`_` are escaped, and the box follows the CURRENT query — a filter it cannot AND into hides it and drops the term instead of showing one that is not applied
* GROK-20298: Cap banners where they were missing: grid mode now runs the count like the gallery modes, and an entity page's child grid asks for the list's row cap instead of the server's default page size
* GROK-20298: `DomainAppViewOptions.query` seeds the page (the "my campaigns" pattern) when the URL carries no query of its own, and `confirmDiscard` is no longer among the options — the page IS the gate
* GROK-20298: A successful form save keeps the page's loaded values and version current from the server's own answer, so a cancelled reload behind it can no longer produce a phantom version conflict
* GROK-20298: One predicate decides whether an action changed the row (keyed on the platform's ribbon icons, not on captions that flip like 'Watch'/'Unwatch') — the list and the entity page used to disagree about History and Watch
* GROK-20298: An entity page's child grid is mounted in a sized box, so it fills the pane instead of rendering at the viewer's default 400x300; a slow context menu no longer opens over another item (or a detached list); list and row pages carry distinct view types; the prompt releases its dialog subscription

* GROK-20298: Added the app framework — `EntityListWidget` (the "list of entities" an app opens on: platform-rendered cards, a brief list or an editable `DomainGrid`, search over the table's identity columns, per-item commands from the handler resolved on demand, the built-in Domain View's row cap and count banner, New gated on `canInsert`) and the view hierarchy `AppView` / `DomainAppView` / `DomainEntityAppView` — a browse/CRUD app whose subclass overrides nothing: list page with the `DomainQuery` ⇄ URL round trip (plus the reserved `view=` / `entity=` params), a row page with the reflective form, a tab per child table (editable `DomainGrid` with the parent FK prefilled), history, and the row's own permission-gated actions
* GROK-20298: Added the save/discard prompt (`promptUnsavedChanges` / `confirmDiscardChanges`) — the refresh policy the editing controls deliberately do not have: every rebuild an `AppView` or an `EntityListWidget` performs asks first (save / discard / cancel), a failed save cancels the navigation, and a save in flight refuses instead of prompting; the app's status bar carries the pending-change count with Save and Discard
* GROK-20298: Added `domainHandler(table)` — the registered `DomainObjectHandler` subclass for a table, or the reflective default; `DomainGridOptions.defaults` prefills rows added through the toolbar (how a detail grid sets its parent FK)
* GROK-20298: A grid built outside the DOM no longer keeps the viewer's default 400x300 size when mounted in a page
