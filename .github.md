# CI in `public/`

`public/` is one pnpm workspace with a Turborepo task graph, so CI installs once at the root and
builds only what a change affects. Workflows live in `.github/workflows/`.

| Workflow | Trigger | What it does |
|---|---|---|
| `workspace.yaml` | push to `master`/`release/**`, PRs touching packages, libraries, js-api, tools, build-config, the lockfile | `pnpm install --frozen-lockfile`, then `turbo run build` for everything the diff affects (dependents included); `typecheck` and `lint` run as reports (`continue-on-error`) until their baselines are clean. On `master`, publishes every changed package whose version is not on npm yet (0.x never publishes) via `pnpm pack` + `npm publish --provenance`. |
| `packages.yaml` | push/PR touching `packages/**` | The stand-based package tests: per changed package, builds it and its `grok.testDependencies` with turbo, boots a Datagrok stand in Docker, `grok publish`es the test dependencies and the package, runs `grok test`. |
| `js-api.yml`, `libraries.yaml`, `tools.yml` | push/PR to those folders | Still on per-project `npm install`; must move to the workspace before merge (same recipe as `packages.yaml`). |
| `linter.yaml`, `gitleaks.yaml`, `security_scan_*.yaml`, `docusaurus.yaml`, `misc.yaml` | various | Unchanged by the workspace. |

Rules that follow from the workspace:

- Never `npm install` inside a package or in `js-api` in CI; the specifiers `workspace:^` and
  `catalog:` are pnpm-only. Install once at the root.
- The `grok` used by a job is the workspace one (`node_modules/.bin` is put on `PATH` after
  install), not a global `datagrok-tools@latest`.
- A plugin needed on the test stand is declared in `grok.testDependencies` in its package.json, not
  as a devDependency: plugin-to-plugin devDependencies created cycles in the build graph.
- Publishing to npm goes through `pnpm pack` so the packed package.json carries real version ranges;
  see `.github/NPM_TRUSTED_PUBLISHING.md` for the OIDC side, which is unchanged.
