# CI in `public/`

`public/` is one pnpm workspace with a Turborepo task graph, so CI installs once at the root and
builds only what a change affects. Workflows live in `.github/workflows/`.

| Workflow | Trigger | What it does |
|---|---|---|
| `workspace.yaml` | push to `master`/`release/**`, PRs touching packages, libraries, js-api, tools, build-config, the lockfile | `pnpm install --frozen-lockfile`, then `turbo run build` for everything the diff affects (dependents included); `typecheck` and `lint` run as reports (`continue-on-error`) until their baselines are clean. It never publishes. |
| `packages.yaml` | push/PR touching `packages/**` | The stand-based package tests: per changed package, builds it and its `grok.testDependencies` with turbo, boots a Datagrok stand in Docker, `grok publish`es the test dependencies and the package, runs `grok test`. On `master`, publishes the package to npm when its version is new, is 1.0.0 or later, and its `datagrok-api`/library dependencies are already on npm. |
| `js-api.yml`, `libraries.yaml`, `tools.yml` | push/PR to those folders | Root install, `turbo run build` with a filter for the project, tests; on `master`, publish a new version to npm via `pnpm pack` + `npm publish <tarball>`. |
| `python-api.yml` | push/PR touching `python-api/**` | Builds `ApiTests` with turbo from a sparse checkout, publishes it to a stand, runs the Python API tests. |
| `docusaurus.yaml` | push/PR changing the `help` submodule pointer, `docusaurus/**`, `js-api/**` | `docusaurus/` is its own npm project; the js-api dependencies it documents are built with turbo. |
| `linter.yaml`, `gitleaks.yaml`, `security_scan_*.yaml`, `misc.yaml` | various | Unchanged by the workspace (`misc/*` is outside it). |

Rules that follow from the workspace:

- Never `npm install` inside a package or in `js-api` in CI; the specifiers `workspace:^` and
  `catalog:` are pnpm-only. Install once at the root.
- The `grok` used by a job is the workspace one (`node_modules/.bin` is put on `PATH` after
  install), not a global `datagrok-tools@latest`.
- A plugin needed on the test stand is declared in `grok.testDependencies` in its package.json, not
  as a devDependency: plugin-to-plugin devDependencies created cycles in the build graph.
- Publishing to npm goes through `pnpm pack` so the packed package.json carries real version ranges;
  see `.github/NPM_TRUSTED_PUBLISHING.md` for the OIDC side, which is unchanged.

## Known traps

- **`packages.yaml` passes `--skip-playwright`.** Nothing here runs `npx playwright install`;
  datagrok-tools < 6.5.6 reported the empty Playwright run as a pass, 6.5.6+ fails it. Jenkins
  owns the Playwright suites.
- **Only changed packages build and test**, so most packages' tests almost never run here, and a
  `workflow_dispatch` on master is not a full-matrix baseline either. Touching every
  `package.json` builds the whole matrix and surfaces a long tail of unrelated failures — budget
  for that before reading a full-matrix run as a regression.
- **Cost:** the repo is public, so standard runners are free; the only billed compute is the
  larger runner `ubuntu-latest-m` (Packages chem/admetica/JKG jobs). Runaways are the risk, hence
  `concurrency: cancel-in-progress` on non-protected refs and job/step timeouts. Real billing:
  `gh api organizations/datagrok-ai/settings/billing/usage?year=Y&month=M` (job wall-clock
  overcounts billed minutes ~7×).
- **Spending-cap wedge:** when the monthly Actions limit is hit, `ubuntu-latest-m` jobs sit queued
  forever and hold the `Packages-refs/heads/master` concurrency group; GitHub keeps one queued run
  per group, so every later master push/dispatch cancels the previous queued one and publishes
  silently die. Recovery: find the holder with
  `gh api repos/datagrok-ai/public/actions/workflows/packages.yaml/runs?status=queued`
  (`gh run list --limit N` misses old runs), `gh run cancel` it and anything behind it, then
  `gh workflow run packages.yaml --repo datagrok-ai/public --ref master -f packages=<Pkg>`.
  Check a run's `conclusion`, not just completion — `cancelled` is not green.
- Give `workflow_dispatch` runs their own concurrency group, so a push cannot cancel a manual
  publish.
- The ApiTests check is only meaningful when its "Build unpublished dependencies" step really
  links the local js-api; otherwise it silently tests the npm `datagrok-api`.
