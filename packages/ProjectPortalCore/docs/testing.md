# Tests

What the package tests and BDD scenarios cover. How to run them is in the package [README](../README.md#tests).

- Compounds on the example data: roles, a compound in two programs, history, a manual change, idempotence.
- Work units on the example data: series, campaigns, studies, process stages; a rejected row; idempotence.
- Readiness on the example data: hit-to-lead and lead-optimization conditions, development lots, the gate.
- The portfolio table: one row per program, stage order, readiness and days in stage against `programReadiness` and the transition log, compounds and work units, filters, the linked readiness matrix, and a restricted user's rows.
- Integration against the example portfolios: feeds, authority, lineage, overlap, routing, gate decisions.
- Schema round-trips: the run-selection loop and the workspace vocabulary.
- The workspace builder: tree, idempotence, preview, a renamed program, concurrent builds, stage folders from the builder and on advance, the orphan report.
- Data package: the rules (criteria to the next gate in stage order with state and basis, each section's status and source, a stale evidence table, a selected and a reference run, the summary, CSV quoting, the file name), and on EX-BIOC the lines of EXB-201 (criteria of D1 to D5, its example documents, its dataset), a scratch project's saved run with its model, unit operation, run type and author, the functions and the dialog.

## BDD scenarios (`npm run test:bdd`)

Gherkin scenarios in `bdd/features/`, compiled to Playwright by `@datagrok-libraries/bdd`. Features address
controls only by their `data-u2-name`. Run them one worker at a time (`--workers=1`): scenarios share the
example portfolios on one server. A guide tour (`bdd/features/guides/portfolios-tour.feature`) renders a film of
the multi-portfolio board from a passing scenario.

## Known failures

Two package tests fail on purpose until the platform is fixed; they are the acceptance checks:
- `a manually created program stays private until shared`, on GROK-21041 (a domain row cannot be granted; see
  [platform-findings.md](platform-findings.md), item 1). The other isolation test passes since program rows are
  linked into their workspace folders;
- saving a model run with its soft reference, on GROK-21042 (item 20). `saveModelRun` falls back to `run_id`
  meanwhile.

Tests that need a second person (approval review, program roles) create throwaway users, block them afterwards,
and put every example portfolio back as they found it.
