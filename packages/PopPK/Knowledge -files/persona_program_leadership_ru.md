# Персона: Руководитель программы (PM)

## Карточка персоны

| Атрибут | Детали |
|---------|--------|
| **Роль** | VP Clinical Development / Program Lead / Head of Clinical Pharmacology |
| **Отдел** | Клиническая разработка, руководство R&D |
| **Организация** | Big Pharma, средний биотех |
| **Размер команды** | Курирует 20–100+ человек в клинической фармакологии, фармакометрике и медицинских функциях |
| **Образование** | MD, PharmD или PhD; часто с MBA или управленческой подготовкой |
| **Опыт** | 15–25+ лет в разработке лекарств; 5+ в руководстве |
| **Подчинение** | Chief Medical Officer, SVP R&D или CEO (биотех) |
| **Бюджетные полномочия** | Утверждает годовые бюджеты ПО/услуг $500K–$5M+; подписывает контракты с CRO |

### Профиль

Руководитель программы принимает высокозначимые решения, зависящие от результатов моделирования и симуляции: какую дозу продвигать в Phase 3, проводить ли отдельное исследование при нарушении функции почек или положиться на экстраполяцию PopPK, как ответить на Complete Response Letter FDA. Не строит и не запускает модели — потребляет результаты в виде forest plots, дашбордов симуляций и executive summary. Главная фрустрация — время ответа и непрозрачность процесса моделирования: задаёшь вопрос сегодня, получаешь ответ через неделю, без возможности интерактивно исследовать последствия.

### Цели

- Принимать своевременные решения на основе данных по выбору дозы и стратегии клинической разработки
- Минимизировать время и стоимость программы разработки при максимизации вероятности регуляторного успеха
- Доносить ценность M&S до исполнительного комитета и совета директоров
- Обеспечить соответствие регуляторным ожиданиям (ICH M15, FDA MIDD)

### Текущие инструменты

PowerPoint, PDF-отчёты, email, дашборды (Tableau/Spotfire — редко для PMx), системы управления клиническими исследованиями

### Болевые точки

- **Недельное время ответа**: «Что если мы дозируем 200 мг BID вместо 300 мг QD?» занимает неделю, потому что PMx должен перезапустить симуляции
- **Непрозрачность**: не может увидеть, как работает модель, не может оспорить допущения, вынужден доверять чёрному ящику PMx
- **Статичные материалы**: получает слайды PowerPoint с замороженными графиками — нельзя углубиться, изменить параметры или исследовать сценарии
- **Цена нерешительности**: каждая неделя задержки в выборе дозы стоит $500K–$2M в таймлайне разработки; неверный выбор дозы может убить программу стоимостью $1B
- **Коммуникация с советом директоров**: сложно объяснить модельные доказательства нетехническим руководителям и инвесторам

### Что нужно от PopPK Studio

- Интерактивный дашборд: выбираешь дозу, популяцию, сценарий → видишь предсказанные исходы в реальном времени
- Вид сравнения сценариев: режимы дозирования side-by-side с вероятностью достижения цели
- Автогенерация executive summary с выделенными ключевыми находками
- Аудит-трейл для документирования решений (что решено, на основе каких данных, когда)
- Доступ с любого устройства (browser-native = не нужны заявки в IT на установку)

### Цитата

> «Мне не важен OFV или матрица омега. Мне важно одно: если я выберу 200 мг для Phase 3, какова вероятность, что мы достигнем цели эффективности в ITT-популяции? Покажи мне это — живьём, сейчас, на этом совещании.»

## User Journey Map

### Сценарий: Выбор дозы на портфельном обзоре go/no-go для Phase 3

#### Этап 1 — Получение пакета результатов M&S (день 1)

| Аспект | Детали |
|--------|--------|
| **Задача** | Изучить результаты моделирования и симуляции от команды PMx |
| **Действия** | Получить финальный PopPK/PD отчёт → прочитать executive summary → изучить симуляции доза-ответ → определить вопросы для команды |
| **Текущий опыт** | 40-страничный PDF по email; беглый просмотр executive summary; вопросы помечены для обсуждения на следующей неделе |
| **Опыт в PopPK Studio** | Уведомление о завершении анализа → открыть интерактивный дашборд → просмотреть ключевые результаты → углубиться в конкретные графики → закладки вопросов для PMx |
| **Эмоция** | Сейчас: перегрузка (плотный отчёт) → PopPK Studio: ориентация (интерактивный обзор) |
| **Ключевая метрика** | Время до понимания ключевых находок |

#### Этап 2 — Исследование сценариев (день 1–3)

| Аспект | Детали |
|--------|--------|
| **Задача** | Оценить альтернативные стратегии дозирования перед governance-совещанием |
| **Действия** | Сравнить 150 мг BID vs. 200 мг QD vs. 300 мг QD → проверить предсказанные пределы безопасности → оценить особые популяции (пожилые, нарушение функции почек) → оценить плато доза-ответ |
| **Текущий опыт** | Email фармакометристу: «Можете ещё симулировать 150 мг BID?» → ожидание 3–5 дней → обновлённые слайды |
| **Опыт в PopPK Studio** | Открыть дашборд сравнения сценариев → переключать режимы → фильтры популяции (возраст > 65, СКФ < 60) → увидеть распределения Cmax и достижение цели → сохранить предпочтительный сценарий |
| **Эмоция** | Сейчас: фрустрация (ожидание, нельзя исследовать) → PopPK Studio: полномочия (исследование в реальном времени) |
| **Ключевая метрика** | Количество исследованных сценариев; время от вопроса до ответа |

#### Этап 3 — Governance-совещание (день 5)

| Аспект | Детали |
|--------|--------|
| **Задача** | Представить рекомендацию по дозе комитету по управлению клинической разработкой |
| **Действия** | Представить M&S-обоснованный выбор дозы → ответить на вопросы комитета → задокументировать решение и обоснование |
| **Текущий опыт** | Статичные слайды; комитет спрашивает «а что с меньшей дозой для пожилых?» → «Мы вернёмся после следующего цикла моделирования» → решение откладывается на 2 недели |
| **Опыт в PopPK Studio** | Презентация с живого дашборда → член комитета спрашивает про пожилых → фильтр популяции на экране → предсказанная экспозиция → решение принято на совещании |
| **Эмоция** | Сейчас: фрустрация (нельзя ответить, задержка решения) → PopPK Studio: решительность (доказательства в реальном времени) |
| **Ключевая метрика** | Решения на совещание; сэкономленные дни задержки |

#### Этап 4 — Документирование и коммуникация решения (день 5–7)

| Аспект | Детали |
|--------|--------|
| **Задача** | Задокументировать решение о выборе дозы с подтверждающими данными для регуляторного трейла и внутренней коммуникации |
| **Действия** | Зафиксировать обоснование решения → привязать к поддерживающим анализам → коммуницировать расширенной команде → архивировать для регуляторной ссылки |
| **Текущий опыт** | Протокол совещания в Word; прикреплённый PDF-отчёт; email заинтересованным сторонам |
| **Опыт в PopPK Studio** | Фиксация решения в один клик с привязкой к версии модели, исследованным сценариям и заметкам комитета → автогенерация executive brief → ссылка на дашборд расширенной команде → постоянная аудируемая запись |
| **Эмоция** | Сейчас: административная нагрузка → PopPK Studio: бесшовное документирование |
| **Ключевая метрика** | Время документирования решения; качество прослеживаемости |
