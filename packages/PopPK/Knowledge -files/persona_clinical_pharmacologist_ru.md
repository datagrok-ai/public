# Персона: Клинический фармаколог (CP)

## Карточка персоны

| Атрибут | Детали |
|---------|--------|
| **Роль** | Клинический фармаколог |
| **Отдел** | Клиническая фармакология, клиническая разработка |
| **Организация** | Big Pharma, средний биотех |
| **Размер команды** | 10–50 человек (Big Pharma); 3–10 (биотех) |
| **Образование** | PharmD, MD или PhD в фармакологии / клинической фармакологии |

| **Бюджетные полномочия** | Влияет на бюджеты ПО и CRO на уровне программы |

### Профиль

Клинический фармаколог — стратегический принимающий решения, который переводит результаты моделирования в клинические действия. Владеет стратегией клинической фармакологии программы: обоснование выбора дозы, рекомендации для особых популяций (нарушение функции почек/печени, педиатрия, пожилые), оценка лекарственных взаимодействий, разделы Clinical Pharmacology этикетки препарата. Заказывает анализы у фармакометристов, но всё чаще хочет проводить базовые модели и симуляции самостоятельно — особенно сценарии «что если?» во время совещаний.

### Цели

- Формировать рекомендации по дозированию на основе данных, выдерживающие регуляторную проверку
- Предвосхищать вопросы FDA/EMA о вариабельности PK и обоснованности дозировки
- Доносить сложные PK/PD концепции до клинических команд, медицинских отделов и руководства
- Снизить зависимость от фармакометристов для исследовательских анализов

### Текущие инструменты

Phoenix WinNonlin (преимущественно NCA), Excel, R (базовый уровень), PowerPoint, forest plots от фармакометриста, клинические базы данных

### Болевые точки

- **Зависимость-бутылочное горлышко**: каждый вопрос «что если?» требует от фармакометриста правки кода, перезапуска и доставки результатов — ожидание дни–недели
- **Фрустрация чёрного ящика**: получает результаты модели, но не может интерактивно исследовать модель, изменить допущение о ковариате или запустить быструю симуляцию
- **Разрыв перевода**: сложно связать детали модели на уровне OFV с клиническими вопросами («что это значит для пациента 90 кг с ХБП 3 стадии?»)
- **Пропасть NCA → PopPK**: уверенно работает с NCA в Phoenix, но переход к PopPK на NONMEM требует совершенно других навыков и инструментов
- **Сборка отчётов**: ручное объединение выходных данных фармакометриста с клинической интерпретацией для регуляторных документов

### Что нужно от PopPK Studio

- Workflow через GUI: выбор модели, оценка параметров и диагностика «кликами»
- Библиотека готовых моделей с визуальными диаграммами компартментов и описаниями на понятном языке
- Интерактивная «песочница» симуляций: меняешь дозу, вес тела, функцию почек → мгновенно видишь предсказанный PK-профиль
- Генератор forest plots ковариатных эффектов с подсказками для клинической интерпретации
- Плавный переход NCA → PopPK в рамках одной платформы
- Экспортируемые графики и таблицы, форматированные для регуляторных документов

### Цитата

> «Я не хочу учить синтаксис NONMEM. Я хочу выбрать двухкомпартментную модель, указать на свои данные и исследовать, что произойдёт, если я изменю дозу для педиатрического пациента 40 кг — всё до следующего совещания.»

## User Journey Map

### Сценарий: Подготовка обоснования дозировки для встречи End-of-Phase-2 с FDA

#### Этап 1 — Обзор доступных данных (день 1–2)

| Аспект | Детали |
|--------|--------|
| **Задача** | Понять ландшафт PK-данных по исследованиям Phase 1 и Phase 2a |
| **Действия** | Обзор NCA-сводки Phase 1 → изучение профилей концентрация-время → выявление паттернов вариабельности → проверка покрытия ковариат (диапазоны веса, возраста, функции почек) |
| **Текущий опыт** | Запрос сводок у биостатистика; просмотр NCA-выхода Phoenix; ручной просмотр клинической базы данных |
| **Опыт в PopPK Studio** | Открыть интегрированный обозреватель данных → визуальное наложение профилей концентрация-время по исследованию/дозе → дашборд распределения ковариат → автоматическое выявление субъектов с разреженным vs. плотным отбором проб |
| **Эмоция** | Сейчас: пассивность (ожидание чужих выходных данных) → PopPK Studio: вовлечённость (прямое исследование данных) |
| **Ключевая метрика** | Время до формирования первичной PK-оценки |

#### Этап 2 — Заказ или самостоятельный запуск PopPK-анализа (день 2–10)

| Аспект | Детали |
|--------|--------|
| **Задача** | Получить популяционную PK-модель соединения |
| **Действия** | Если PMx доступен: постановка задачи, ожидание результатов. Если самообслуживание: выбор модели из библиотеки → запуск оценки → проверка диагностики |
| **Текущий опыт** | Запрос на анализ → ожидание 1–3 недели → получение пакета результатов → уточняющие вопросы |
| **Опыт в PopPK Studio** | Открыть библиотеку моделей → выбрать «2-комп. пероральная, абсорбция 1-го порядка» → автонастройка из данных → нажать «Оценить (SAEM)» → проверить автосгенерированную диагностику → доработать или эскалировать к PMx для сложных случаев |
| **Эмоция** | Сейчас: фрустрация (зависимость, задержки) → PopPK Studio: автономность (самообслуживание для 70% случаев) |
| **Ключевая метрика** | Дни от потребности в анализе до первых результатов |

#### Этап 3 — Исследование доза-экспозиция-ответ (день 10–18)

| Аспект | Детали |
|--------|--------|
| **Задача** | Оценить зависимости доза-экспозиция и определить оптимальную дозу для Phase 2b |
| **Действия** | Симуляция нескольких режимов → наложение распределений предсказанных AUC/Cmax → маппинг на пороги эффективности и безопасности → оценка влияния ковариат на достижение цели |
| **Текущий опыт** | Запрос конкретных сценариев у PMx → ожидание → статичные графики → запрос модификаций → повторное ожидание |
| **Опыт в PopPK Studio** | Открыть песочницу симуляций → двигать слайдеры (доза: 100→200→400 мг; вес: 50→120 кг; СКФ: 30→120 мл/мин) → обновление PK-профиля в реальном времени → переключение порогов эффективности/безопасности → сохранение сценариев |
| **Эмоция** | Сейчас: нетерпение (невозможно итерировать быстро) → PopPK Studio: открытие (исследование пространства дизайна) |
| **Ключевая метрика** | Количество оценённых дозовых сценариев; время до рекомендации |

#### Этап 4 — Построение нарратива обоснования дозы (день 18–25)

| Аспект | Детали |
|--------|--------|
| **Задача** | Сконструировать аргументацию клинической фармакологии для предложенного дозирования Phase 2b |
| **Действия** | Forest plots ковариатных эффектов → сводка доза-экспозиция-ответ → рекомендации для особых популяций → черновик раздела Clinical Pharmacology |
| **Текущий опыт** | Сбор графиков от PMx, NCA-таблиц из Phoenix, клинических данных → ручная сборка в PowerPoint/Word |
| **Опыт в PopPK Studio** | Forest plot в один клик → экспорт графиков доза-ответ → автозаполнение регуляторного шаблона с привязанными к модели таблицами → редактирование нарратива в платформе |
| **Эмоция** | Сейчас: рутинная сборка → PopPK Studio: структурированное повествование |
| **Ключевая метрика** | Время подготовки отчёта; согласованность графиков и текста |

#### Этап 5 — Презентация команде и FDA (день 25–30)

| Аспект | Детали |
|--------|--------|
| **Задача** | Представить обоснование дозы внутреннему комитету и подготовиться к встрече EOP2 с FDA |
| **Действия** | Презентация внутреннему review board → ответы на вопросы с живым исследованием модели → финализация брифинг-документа → презентация на встрече с FDA |
| **Текущий опыт** | Статичный PowerPoint; если спрашивают «а что с дозой X для популяции Y?» → «мы вернёмся с ответом» |
| **Опыт в PopPK Studio** | Презентация с интерактивного дашборда → ответы на ad-hoc вопросы живыми симуляциями прямо на встрече → немедленный экспорт обновлённых сценариев |
| **Эмоция** | Сейчас: тревога (не готов к незапланированным вопросам) → PopPK Studio: уверенность (могу ответить в реальном времени) |
| **Ключевая метрика** | Способность отвечать на ad-hoc вопросы; результаты встречи |
