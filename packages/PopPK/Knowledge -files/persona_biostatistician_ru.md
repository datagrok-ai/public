# Персона: Биостатистик (BS)

## Карточка персоны

| Атрибут | Детали |
|---------|--------|
| **Роль** | Биостатистик / Statistical Scientist |
| **Отдел** | Биостатистика, статистическое программирование |
| **Организация** | Big Pharma, CRO |
| **Размер команды** | 50–200 человек (Big Pharma); 20–100 (крупная CRO) |
| **Образование** | PhD или MS в биостатистике, статистике или математике |
| **Опыт** | 3–20 лет в статистике клинических исследований |
| **Подчинение** | Руководитель биостатистики или VP Biometrics |
| **Бюджетные полномочия** | Влияет на закупки статистического ПО (SAS, R, East) |

### Профиль

Биостатистик проектирует клинические исследования, пишет планы статистического анализа (SAP) и выполняет первичные анализы эффективности/безопасности. Его мир сосредоточен вокруг MMRM, ANCOVA, анализа выживаемости и расчёта размера выборки — всё в SAS или R. Пересекается с фармакометрикой в двух точках: exposure-response (E-R) анализ, связывающий экспозицию препарата с клиническими исходами, и MMRM-анализ продольных конечных точек, где метрики экспозиции из PopPK-модели используются как ковариаты. Строг в статистической методологии, но часто воспринимает фармакометрическое моделирование как параллельную дисциплину с незнакомыми инструментами и терминологией.

### Цели

- Обеспечить статистически строгие анализы клинических исследований в регуляторные сроки
- Корректно обрабатывать пропущенные данные, множественность и фреймворки эстимандов (ICH E9(R1))
- Эффективно взаимодействовать с фармакометристами по E-R анализам без фрагментации инструментов
- Внедрять воспроизводимые, валидированные workflow, удовлетворяющие требованиям GxP

### Текущие инструменты

SAS (PROC MIXED, PROC GLIMMIX, PROC PHREG), R (lme4, mmrm, survival), East/nQuery (размер выборки), Pinnacle 21 (CDISC), Git/SVN

### Болевые точки

- **Два мира без интеграции**: MMRM в SAS и PopPK в NONMEM полностью разъединены — разные форматы данных, разное ПО, разные команды, разные отчёты
- **Трение при передаче E-R данных**: получение метрик экспозиции из PopPK (AUC, Cmax, Ctrough) требует ручного слияния с датасетами эффективности
- **Воспроизводимость между инструментами**: результаты должны быть прослеживаемы от сырых SDTM-данных через анализ до регуляторных таблиц — кросс-инструментные пайплайны разрывают аудит-трейл
- **Барьер кривой обучения**: выиграл бы от понимания PopPK-диагностики, но кривая обучения NONMEM слишком крутая для эпизодического использования

### Что нужно от PopPK Studio

- Бесшовный импорт индивидуальных метрик экспозиции из PopPK в свои аналитические датасеты
- Функциональность MMRM в той же платформе (или чистая R-интеграция для lme4/mmrm)
- Модуль E-R анализа, связывающий выход PopPK и статистические конечные точки
- Валидированная, GxP-ready вычислительная среда с аудит-трейлом
- Привычный R/SAS-подобный интерфейс — не чужеродный DSL

### Цитата

> «Я трачу два дня на каждый E-R анализ только на слияние индивидуальных экспозиций от фармакометриста с моим датасетом эффективности и проверку корректности джойнов. Если бы всё было на одной платформе с прослеживаемой линейностью данных, я бы экономил неделю на исследование.»

## User Journey Map

### Сценарий: Exposure-response анализ для первичной конечной точки эффективности Phase 3

#### Этап 1 — Получение метрик экспозиции (день 1–3)

| Аспект | Детали |
|--------|--------|
| **Задача** | Получить индивидуальные метрики экспозиции (AUC, Cmax, Ctrough) из PopPK-модели |
| **Действия** | Получить CSV с индивидуальными post-hoc оценками от PMx → валидировать ID субъектов → слить с ADEFF-датасетом → QC слияния (пропущенные субъекты, дубликаты) |
| **Текущий опыт** | Email от PMx с CSV-вложением; ручное слияние в SAS; часы QC-проверок |
| **Опыт в PopPK Studio** | Метрики экспозиции автогенерируются из PopPK-модели → доступны как связанный датасет в Datagrok → слияние с данными эффективности в один клик → визуальный дашборд валидации слияния |
| **Эмоция** | Сейчас: рутина (ручная «сантехника» данных) → PopPK Studio: лёгкость (автосвязывание) |
| **Ключевая метрика** | Время от завершения модели до готового E-R датасета |

#### Этап 2 — Разведочный E-R анализ (день 3–7)

| Аспект | Детали |
|--------|--------|
| **Задача** | Исследовать зависимость между экспозицией и конечными точками эффективности/безопасности |
| **Действия** | Scatter plots AUC vs. ответ → анализ по квартилям экспозиции → логистическая регрессия (бинарные точки) → предварительный MMRM с ковариатой экспозиции |
| **Текущий опыт** | SAS-программы или R-скрипты; ручная генерация каждого графика; отдельный код для каждой точки |
| **Опыт в PopPK Studio** | Интегрированный E-R explorer → автогенерация графиков по квартилям → логистическая/линейная регрессия кликом → MMRM с экспозицией как time-varying ковариатой |
| **Эмоция** | Сейчас: рутинное программирование → PopPK Studio: интерактивное исследование |
| **Ключевая метрика** | Количество исследованных E-R зависимостей; время до первого сигнала |

#### Этап 3 — Формальное E-R моделирование (день 7–15)

| Аспект | Детали |
|--------|--------|
| **Задача** | Построить финальную exposure-response модель для регуляторной подачи |
| **Действия** | Фит Emax / линейной / логистической E-R модели → ковариатные эффекты на E-R → выбор модели (AIC/BIC) → анализ чувствительности → регуляторные таблицы и графики |
| **Текущий опыт** | SAS PROC NLMIXED или R nls/nlme; отдельный код для каждой модели; ручная генерация таблиц |
| **Опыт в PopPK Studio** | Библиотека E-R моделей → сравнение моделей side-by-side → автоматический анализ чувствительности → генерация регуляторных таблиц в один клик с прослеживаемостью данных |
| **Эмоция** | Сейчас: аккуратно, но медленно → PopPK Studio: та же строгость, быстрее исполнение |
| **Ключевая метрика** | Время до финальной E-R модели; время подготовки регуляторных таблиц |

#### Этап 4 — Кросс-функциональный обзор и отчётность (день 15–20)

| Аспект | Детали |
|--------|--------|
| **Задача** | Согласовать E-R результаты с командой PMx и подготовить объединённый раздел Clinical Pharmacology/Statistics |
| **Действия** | Обзор E-R находок с PMx → обеспечить согласованность PopPK-отчёта и E-R отчёта → вклад в интегрированную сводку → финализация статистических таблиц CSR |
| **Текущий опыт** | Совещания для сверки выходных данных разных инструментов; ручное перекрёстное сравнение; отдельные разделы отчётов |
| **Опыт в PopPK Studio** | Общее рабочее пространство с PMx → E-R результаты напрямую связаны с PopPK-моделью → единая генерация отчётов → единый источник истины для всех цифр |
| **Эмоция** | Сейчас: трение (согласование параллельных workflow) → PopPK Studio: синхронизация (общая платформа) |
| **Ключевая метрика** | Количество циклов согласования; время выравнивания между командами |
