### Профиль

Фармакометрист — основной «тяжёлый» пользователь PopPK Studio. Строит популяционные PK/PD модели полного цикла: от выбора структурной модели и спецификации случайных эффектов через ковариатный анализ до квалификации модели и регуляторной отчётности. Мыслит категориями падения OFV, процентов η-shrinkage и распределений CWRES. Проводит 60–80% рабочего времени в NONMEM + R, переключаясь между 4–6 разрозненными инструментами в рамках одного анализа.

### Цели

- Строить научно обоснованные PopPK/PD модели, выдерживающие регуляторную экспертизу
- Укладываться в сроки по регуляторным подачам и клиническим milestone'ам
- Воспроизводить и развивать модели из предыдущих исследований или литературы
- Наставлять младших моделеров и устанавливать лучшие практики в команде

### Текущие инструменты

NONMEM, Monolix, R (nlmixr2, xpose, vpc, ggPMX), PsN, Pirana, SAS (эпизодически), Git, Word/PowerPoint для отчётов

### Болевые точки

- **Фрагментированный workflow**: жонглирование 4–6 инструментами (NONMEM → R → PsN → Excel → Word) с ручным переносом данных между ними
- **Ад отладки**: часы на устранение синтаксических ошибок в control stream'ах NONMEM с криптичными сообщениями Fortran-компилятора
- **Отсутствие коллаборации**: обмен моделями через email/сетевые диски; нет системы контроля версий по умолчанию; «какой control stream финальный?»
- **Медленные итерации**: ожидание очереди на кластере; нет интерактивного исследования поведения модели
- **Бремя воспроизводимости**: ручное документирование каждого шага для регуляторного аудита

### Что нужно от PopPK Studio

- Контроль на уровне кода над спецификацией модели (DSL с подсветкой синтаксиса, автодополнением)
- Полный набор методов оценки: FOCE-I, SAEM, MAP — совпадение OFV с NONMEM до 3+ значащих цифр
- Встроенная диагностика (GOF, VPC, CWRES) без переключения в R
- Совместимость с NONMEM: импорт/экспорт control stream'ов
- Версионированный, аудируемый workflow анализа
- Производительность: оценка за секунды, а не минуты

### Цитата

> «Мне не нужен ещё один GUI, который прячет математику. Мне нужна та же мощность, что у NONMEM, но без workflow эпохи Fortran. Покажи мне OFV, покажи градиенты, дай скриптовать всё — но в современной среде.»

## User Journey Map

### Сценарий: PopPK-анализ для перорального препарата Phase 2b, регуляторная подача через 8 недель

#### Этап 1 — Сборка данных (день 1–3)

| Аспект | Детали |
|--------|--------|
| **Задача** | Объединить записи дозирования, PK-пробы и ковариаты в готовый для анализа датасет |
| **Действия** | Импорт SDTM/ADaM датасетов → маппинг в формат NMTRAN → обработка BQL-записей (метод M3) → QC-проверки (дубликаты, временные последовательности, пропущенные ковариаты) → сводная статистика |
| **Текущий опыт** | Ручные R-скрипты или SAS-программы; ошибки при слиянии CSV-файлов; часы на кодирование EVID/CMT |
| **Опыт в PopPK Studio** | Drag-and-drop импорт → автоматическое распознавание NMTRAN-колонок → визуальная разметка BQL → встроенные QC-правила с предложениями исправлений → дашборд сводки данных |
| **Эмоция** | Сейчас: раздражение (рутина, ошибки) → PopPK Studio: уверенность (валидировано, визуально) |
| **Ключевая метрика** | Время от сырых данных до готового датасета |

#### Этап 2 — Разработка базовой модели (день 3–10)

| Аспект | Детали |
|--------|--------|
| **Задача** | Выбрать структурную PK-модель, определить иерархию случайных эффектов, выбрать модель остаточной ошибки |
| **Действия** | Тестирование 1-комп. vs 2-комп. vs 3-комп. → абсорбция первого порядка vs транзитная → IIV на CL, V, Ka → пропорциональная vs комбинированная ошибка → сравнение OFV, AIC, диагностики |
| **Текущий опыт** | Правка control stream в текстовом редакторе → отправка на кластер → ожидание → проверка → правка → повтор (10–30 итераций) |
| **Опыт в PopPK Studio** | Выбор модели из библиотеки или написание на DSL → оценка в браузере (секунды для аналитических моделей) → мгновенные GOF-графики → сравнение моделей в режиме side-by-side → интерактивные итерации |
| **Эмоция** | Сейчас: испытание терпения (медленный цикл) → PopPK Studio: состояние потока (мгновенная обратная связь) |
| **Ключевая метрика** | Количество исследованных моделей в день |

#### Этап 3 — Ковариатный анализ (день 10–20)

| Аспект | Детали |
|--------|--------|
| **Задача** | Выявить факторы пациента, объясняющие межиндивидуальную вариабельность |
| **Действия** | Графики ETA vs ковариаты → скрининг GAM/SCM → прямое включение (ΔOFV > 3,84) → обратное исключение (ΔOFV > 6,63) → forest-графики ковариатных эффектов |
| **Текущий опыт** | Автоматизация PsN SCM (часы-дни) или ручной пошаговый отбор в NONMEM; отдельные R-скрипты для forest plots |
| **Опыт в PopPK Studio** | Интерактивный обозреватель ETA-ковариат → автоматический пошаговый отбор с прогрессом в реальном времени → встроенный генератор forest plots → таблица сравнения моделей обновляется автоматически |
| **Эмоция** | Сейчас: тревога (не пропустил ли ковариату? Правильный ли порядок?) → PopPK Studio: систематическая уверенность |
| **Ключевая метрика** | Время полного цикла ковариатного анализа |

#### Этап 4 — Квалификация модели (день 20–30)

| Аспект | Детали |
|--------|--------|
| **Задача** | Продемонстрировать адекватность модели через bootstrap, VPC и анализ чувствительности |
| **Действия** | Bootstrap 500–1000 реплик → сравнение доверительных интервалов с точечными оценками → генерация pcVPC → анализ чувствительности ключевых допущений |
| **Текущий опыт** | PsN bootstrap на кластере (ночь–дни); VPC через R-пакет vpc; ручная сборка результатов |
| **Опыт в PopPK Studio** | Bootstrap в один клик (параллельно на сервере) → интерактивный VPC с настраиваемым биннингом → встроенный дашборд анализа чувствительности → все результаты привязаны к версии модели |
| **Эмоция** | Сейчас: ожидание (очереди кластера, ночные запуски) → PopPK Studio: продуктивность (результаты к обеду) |
| **Ключевая метрика** | Время от финальной модели до квалифицированной модели |

#### Этап 5 — Симуляция и рекомендации по дозированию (день 30–40)

| Аспект | Детали |
|--------|--------|
| **Задача** | Симулировать альтернативные режимы дозирования, сформировать рекомендации для целевых популяций |
| **Действия** | Определить виртуальные популяции (ковариаты из распределений) → симулировать 1000+ субъектов на режим → рассчитать достижение цели → графики экспозиция-ответ → сравнение режимов |
| **Текущий опыт** | Кастомные R-скрипты с mrgsolve или rxode2; ручная сборка сценариев симуляции |
| **Опыт в PopPK Studio** | Визуальный конструктор симуляций → сценарии через GUI или скрипт → параллельный Monte Carlo в WebWorkers → интерактивный обозреватель доза-ответ → экспорт в шаблон отчёта |
| **Эмоция** | Сейчас: рутина (много скриптов на каждый сценарий) → PopPK Studio: возможности (интерактивное исследование) |
| **Ключевая метрика** | Количество исследованных сценариев; время до рекомендации по дозе |

#### Этап 6 — Регуляторная отчётность (день 40–56)

| Аспект | Детали |
|--------|--------|
| **Задача** | Подготовить PopPK-отчёт для Модуля 2.7.2 подачи eCTD |
| **Действия** | Написание раздела методов → генерация таблиц (оценки параметров, bootstrap CI) → вставка диагностических графиков → документирование решений по построению модели → QC-проверка → финализация |
| **Текущий опыт** | Copy-paste из R/NONMEM в Word; ручное форматирование таблиц; графики как PNG-экспорт; кошмар с версиями |
| **Опыт в PopPK Studio** | Автогенерируемый шаблон отчёта с «живыми» таблицами и графиками → редактирование текста в платформе → экспорт в PDF/Word в один клик → полный аудит-трейл → рецензент может проследить любое число до источника |
| **Эмоция** | Сейчас: страх (самая ненавистная часть) → PopPK Studio: облегчение (автоматизировано, прослеживаемо) |
| **Ключевая метрика** | Время подготовки отчёта; количество QC-ошибок |
