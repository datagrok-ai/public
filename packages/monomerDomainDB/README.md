# monomerDomainDB

Monomer library provider backed by **domain schemas** (Datagrok's entity management system) —
the domain-schema counterpart of the hand-written [monomerDB](../monomerDB) package.

The package ships the `monomers` domain schema ([databases/monomers/schema.json](databases/monomers/schema.json)):

| Table | Security | Purpose |
|---|---|---|
| `library` | `row` (lazy promotion) | A monomer library; business key `name` |
| `monomer` | `master` → `library_id` | One monomer; business key `(library_id, polymer_type, symbol)` |
| `monomer_set` | `row` (lazy promotion) | A monomer set (ambiguous/placeholder monomers) |
| `set_placeholder` | `master` → `set_id` | One placeholder with its JSON links |

On top of it, `DomainDbLibraryProvider` implements the full
`IMonomerLibProvider` contract from `@datagrok-libraries/bio` (libraries, monomers, and sets CRUD)
and registers under the `monomer-lib-provider` function role, so the Bio package discovers it
automatically next to the file-based provider.

What the domain-schema backend gives over library files:

- server-enforced permissions (per-library sharing via lazy promotion; monomers inherit the library's access);
- per-row CRUD with optimistic concurrency instead of whole-file rewrites (no more lost updates);
- business-key **upsert** — `addOrUpdateLibrary` is one batch merge, and periodic sync from a
  corporate source is idempotent by construction;
- an in-transaction audit trail with before/after diffs per monomer;
- queryability (filters, facets, aggregation) and the standard Domains browsing/management UI
  under **Platform > Domains > Monomers** (behind the `enableDomainDatabases` flag);
- a typed client generated by `grok api` ([src/generated/db.ts](src/generated/db.ts)).

`rgroups` and `meta` are stored as JSON strings (domain schemas have no structured JSON column
type yet). The modeled HELM fields (symbol, name, molfile, smiles, polymer/monomer type, author,
id, createDate, naturalAnalog, rgroups, meta) round-trip losslessly through
`getLibraryAsString` / `addOrUpdateLibraryString`; keys outside that set are dropped on import.

## Development

```bash
npm install
npm run build                      # grok api && grok check --soft && webpack
grok publish localhost             # deploys the package and the domain schema
grok test --host localhost         # runs the provider test suite
```
